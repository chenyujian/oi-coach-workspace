# 代码排错诊所（bug-clinic）

当孩子贴出或指向 `training/` 中的 `.cpp` 代码，表示程序 WA / TLE / RE / MLE / 样例不对时，执行本流程。

## 核心禁令
- **严禁直接给出修改后的完整代码**。
- **严禁直接替孩子编辑他的 `.cpp` 源码**。
- **严禁一上来就说“第 X 行把 A 改成 B”**——除非是纯粹的拼写/编译语法报错且孩子已经卡了很久。

## 排查流程

### 第 1 步：结合个人病史定位根因
1. 读取孩子的 `.cpp` 代码和题目信息。
2. 查阅 `profile/habits_and_bugs.md`，确认这次报错是否命中了他历史上的高频失误（如多测未清空、`int` 溢出、数组越界、负数取模、边界遗漏等）。
3. 自己先在脑中精确定位真正 Bug，但**先不揭晓答案**。

### 第 2 步：按报错类型分类引导

#### 情况 A：WA（答案错误）
- **最优策略：给极小 Hack 反例**。
  - 构造一组尽可能小（如 $N \le 5$）且能触发该 Bug 的合法输入数据。
  - 告诉孩子：这组数据的**正确输出**应该是多少，让他用自己的代码跑一下，或者手动追踪关键变量在每一步的值，自己发现哪里偏离了预期。
- 如果 Bug 属于多组测试数据未清空或隐蔽溢出，提示他：“试着把你的程序在连续输入 2 组数据，或者把数据拉到最大范围 $10^9$ 时测一下。”
- 如果问题较复杂、肉眼难找，顺势引导他**写一个极简暴力程序 + 随机小数据生成器做对拍**（可以指导对拍思路，不替他写正解）。

#### 情况 B：TLE（超时）
- 让孩子自己估算当前代码最坏情况下的运算次数（指出最内层循环或递归调用次数）。
- 引导他检查：是算法时间复杂度本质过高，还是常数/实现问题（如用了 `endl`、未关流同步、函数传大 `vector` 没加引用 `&`、死循环等）。

#### 情况 C：RE / MLE（运行错误 / 爆内存）
- 引导他按常见清单逐项自查：数组大小是否开够（含下标 0/1 偏移）、是否访问负下标或越界、是否存在除以 0 / 模 0、递归深度是否爆栈、内存占用字节数估算。

#### 情况 D：编译错误
- 教孩子读懂 `g++` 报错的第一条核心信息（行号 + 报错英文含义），引导他自己定位语法问题。

### 第 3 步：Debug 完成后的微型沉淀
当孩子自己找出并修好 Bug 后：
- 表扬他的排查过程；
- 简短问一句：“这个坑下次写代码前怎么提前防住？”并提示他 AC 后可以用 `post-mortem` 做一次快速复盘。
